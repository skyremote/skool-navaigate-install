Listen to this lesson in my voice

You have a design and the itch to build, so you point Claude at the mockup and say build this. Forty minutes later you have a beautiful login page, half a database, an API that contradicts the frontend, and no idea what is next. The model did not fail. You asked an agent to hold an entire application in its head and improvise. That never holds up.
This module is the scoping step. You hand it the design — Pencil, Figma, a screenshot, a sketch — and a sentence about what the app is for. It writes a plan file: stack, data shape, auth, pages, and the build sliced into phases you can actually ship one at a time. The plan is the output. Not code.

Phases are the whole game

An app of any real size is too big for one agent run. The model loses the thread. So we never ask it to build everything at once. Each phase is one honest session — database, then auth, then the core views. You generate a plan per phase, you open a fresh session per plan, you build phase 1 to completion before phase 2.
It is tempting to fire all seven sessions at once. Resist it. Later phases assume earlier ones exist. Sequential is slower by an hour and saves a day.
There is no /prime. Context is /layer-1 and the files already in the folder. Type /new-app, hand it the design, and do not skip the plan file. Type /aios when phase 1 actually runs.

When you want this in a tab of your own, type /aios-coach. You build it, you put it online, your key. It already knows this course. It is not on navaigate.dev yet.
